# TabulaSense

> カメラでテーブルの上を認識し、**片付け**と**拭き上げ**を自動で行う掃除ロボット。台車が付いており、テーブル間を移動する。
>
> A cleaning robot that sees the table with a camera and automatically **clears** it and **wipes** it down.


## 概要 / Overview

TabulaSense は、施設内を移動し、テーブルの上にある「片付けるべき物」と「拭き取るべき汚れ」をカメラで見分け、
アームで物を回収したあと、ワイパー／モップでテーブル表面を自動で拭き上げるロボットです。
また下げ膳なども行います。スタッフのやり方を見て真似し、言われたことを覚えていく自己学習機能を備えています。


0 案内:
ReferTrack方式で「エプロンの人」「今話した人」のように言葉で相手を決めて確認し、「ついてきて」と言われたらスタッフの後ろをついて動きます。移動しながら、SLAMで壁やテーブルの形を地図に描きつつ自分の位置を把握し、同時にMolmo2-ERが「丸いテーブル」のような目印を地図メモリに書き込みます。スタッフが「ここが3番テーブルね」と教えると、LLMが名前を取り出し、今いる場所に一番近い目印に結び付けます。自動の名前と人が教えた名前が食い違った場合は、人が教えた名前を優先します。

1〜2 理解する:
「窓際のテーブルを拭いて」と言われると、LLMが指示を「動作は拭く、種類はテーブル、窓の近く」に分解します。

場所：地図メモリから条件に合う目印を探します。一つなら決定、複数なら「どちらのテーブルですか？」、一つもなければ「案内してもらえますか？」と聞き返します。
ルール：動作と対象をもとにルール記憶を検索し、該当するものを計画の条件に加えます。例えば「拭く前に物があれば片付ける」「端まで拭く」です。

3 やり方を探す:
動作辞書を言い換えも含めて引きます。「拭く」がなければ「一度やって見せてもらえますか？」と頼み、スタッフが拭く様子を撮影します。その動画を見本として動作辞書に登録し、HOSTが見本をもとに動作を実行できるようにします。手順が複数ある場合（物を片付けてから拭く、など）は、LLMが「つかむ→置く/捨てる→拭く」のように部品動作に分け、足りない部品だけ見せてもらいます。

4〜5 やってみる:

片付け：テーブルに物があれば、ルール記憶で置き場所を探します。わからなければ物を持ってスタッフのところへ戻り、「これはどこに置けばいいですか？」と聞いて、答えを置き場所ルールとして保存します。ゴミ箱のフタが閉じていれば、フタを開ける動作を呼び出します。
拭く：腕が届く範囲には限りがあるので、Molmo2-ERがルールで決まった範囲（例：縁まで）をカバーできる立ち位置を複数決め、Nav2がその位置を順に回ります。各位置では、動作辞書に登録された実行モデル（見本動画を使うHOST、または汎用動作のMolmoAct2）でゆっくり拭きます。

6 確かめる:
カメラで拭き残しを確認し、残っていればその部分をやり直します。確認の基準にはルールも使います。例えば「端まで」のルールがあれば、縁の部分も重点的にチェックします。

7 教わる:



スタッフの指摘は内容で行き先が分かれます。

このとき、スポンジや手の3D軌道を追い、ロボットの手先の目標にします。腕の関節の動きはロボット側で計算（逆運動学）し、届かない部分は台車の位置で補います

動きのずれ（「もう少し強く押して」）：CorrectVLAでその場で補正し、その区間を介入データとして実行記録に残します。
意味・手順の指摘（「端まで拭いて」「物があったら捨てて」）：理由ごとルール記憶に保存し、次回の計画から即座に反映します。
適用範囲が曖昧なら、その場で「全部のテーブルでそうしますか？」と確認します。
既存のルールと食い違う場合は、「前は○○と教わりましたが、変えますか？」と確認してから上書きします。

8 身につける:
夜間学習で扱うのは「どう動くか」だけです。言葉で表せる「何をするか」はルール記憶ですでに反映済みなので、学習には回しません。人が介入した区間を「ここはこう動くべきだった」という正解データに、「OK」「ダメ」の一言を成功ラベルにして、成功例と介入データだけで実行モデルを追加学習します。テストに合格したら、翌日のモデルに反映します。



## 開発目標（MVP） / Development goals (MVP)

XLeRobotをMuJoCoでシミュレーションし、最新論文を実装して精度向上も目指す。
さらに、XLeRobot（マイクアレイ（ReSpeaker等）、安価な2Dのレーザー距離センサー（RPLIDARなど）を搭載）を自費で購入し組み立て、初期は計算はクラウドで行い、自宅で作動するかテストする。
例えば部屋を案内し、「テーブルを掃除して」という抽象的な命令も実行できるようにする。

そして顧客で試験導入しながら精度向上を目指す。
YORのシミュレーションモデルを作成し、YOR(https://yourownrobot.ai/)を助成金で購入しさらにPoCを行う。YORのソフトはアップデートのたびにクラウドを通して遠隔で更新されるようにする。


ソフトウェアは3つの層に分けて開発する。シミュレーションと実機を同じコードで動かせるよう、両者の差は「体の層」だけに閉じ込める。

- **体の層（Body）**：モーター制御、カメラ、移動。シミュレーション版と実機版を差し替え可能にする。
- **スキルの層（Skills）**：「拭く」「つかむ」「置く」など、個別に学習した動作。
- **頭の層（Brain）**：指示理解、地図、計画、ルール記憶、聞き返し。


### Step 0：開発環境の準備
> 構築手順は [docs/setup.md](docs/setup.md)（`bash scripts/setup.sh` で自動構築）

このプロジェクトではUbuntu の中（/home/expo7/TabulaSense）に必要な編集ファイルを用意します。

### Step 1：シミュレーション上にロボットを構築
- XLeRobotのモデルをMuJoCoに読み込む

まずファイルのパスを扱うための機能を読み込みます
```python
from pathlib import Path
```
次にMuJoCo本体とロボットを3D表示するビューアを読み込みます。
```python
import mujoco
import mujoco.viewer
```
次に、このフォルダにはscene.xmlというMuJoCo に「何を、どんな環境・物理条件で表示してシミュレーションするか」を伝える XML 形式の設定ファイルがあります。
そこでMuJoCoはモデルを読み込むときにscene.xml がどこにあるかを知る必要があります。
まず以下のように右側で作った scene.xml のパスを、model_path という名前で使えるようにします。
```python
model_path = 結果
```
ここでもし以下のように書くと、問題が発生します。
```python
model_path = Path("scene.xml")
```
これだと、Python は「ターミナルで今いるフォルダにある scene.xml」を探します。別のフォルダからスクリプトを実行すると、見つからないことがあります。
今回の目的は、/home/expo7/TabulaSense/sim/xlerobot/scene.xmlというパスを

- 自宅に近いテーブルと部屋を再現する
- キーボード／ゲームパッドでアーム・台車・首を操作できるようにする
- 体の層のインターフェース（`move_arm()`、`get_camera_image()`、`move_base()` 等）を定義する

### Step 2：データ収集の仕組み
- シミュレーション内で遠隔操作し、カメラ映像と関節角度を記録する
- LeRobotのデータ形式で保存する
- スクリプトでお手本軌道を自動生成し、データを大量に作る

### Step 3：最初のスキルを学習
- 対象：「天板を端までなぞる」動作
- 軽量モデル（ACT、SmolVLA等）で全体の流れを通したのち、MolmoAct2をファインチューニングする
- 評価スクリプトを作成し、100回試行の成功率で判断する

### Step 4：スキルの追加
- 「つかむ」「置く」「ゴミ箱に入れる」
- 物の色・形・位置、照明をランダム化して学習する（ドメインランダマイゼーション）

### Step 5：移動と地図
- シミュレーション内でLiDARを再現し、slam_toolboxで地図を作成する
- Nav2でテーブル前まで移動する
- Molmo2-ERで目印（「丸いテーブル」等）を検出し、地図メモリに書き込む

### Step 6：頭の層
- LLMで指示を「動作・対象・場所」に分解する
- 地図メモリ・ルール記憶をデータベースとして実装する
- スキルを順番に呼び出す計画部分（つかむ→置く→拭く）
- 聞き返しの会話（最初はテキスト入力、のちに音声認識を接続）

### Step 7：統合テスト
- シミュレーション内で「窓際のテーブルを拭いて」と入力し、移動→片付け→拭き→確認まで通す
- 失敗場面を見直せるよう、ログと動画を記録する

### Step 8：実機への移行
- 体の層を実機版に差し替える
- サーボの応答を計測し、シミュレーションに反映する（システム同定）
- 実機データを数十本収集して最終調整する
- CorrectVLAによる補正を追加する

### Step 9：学習ループ（その後）
- スタッフの指摘をルール記憶に保存する仕組み
- 介入データを用いた追加学習と合格テスト
