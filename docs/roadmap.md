# TabulaSense 開発ロードマップ

最終的な目標は、飲食店などのテーブルで「片付ける物の回収（下げ膳）」と「天板の拭き上げ」を
自動で行うことです。シミュレーションで手法を固め、安価な XLeRobot の実機で顧客試験を行い、
助成金で YOR を導入して本格的な PoC に進みます。

| フェーズ | 内容 | ロボット | 状態 |
|---|---|---|---|
| 0 | シミュレーション環境の構築 | XLeRobot（MuJoCo） | **済（このディレクトリ）** |
| 1 | シミュレーションで認識と方策を作る | XLeRobot（MuJoCo） | 次 |
| 2 | XLeRobot を購入・組み立て、実機で動かす | XLeRobot 実機 | |
| 3 | 顧客の店舗で試験導入し、精度を上げる | XLeRobot 実機 | |
| 4 | YOR のシミュレーションモデルを作り、助成金で購入して PoC | YOR | |

## フェーズ 0: シミュレーション環境（済）

- XLeRobot の上流 MJCF を読み込み、テーブル・食器・汚れ・下げ膳用ビンを足したシーン
- スポンジでの拭き取り（接触していて、かつ動いているときだけ汚れが減る）
- Gymnasium 環境、3 台のカメラ、真値のラベル画像
- テスト 7 件、ウィンドウ表示（`scripts/view.py`）

## フェーズ 1: シミュレーションで認識と方策を作る

### 1-1. 見分ける（認識）

「回収する物」と「拭く汚れ」を画像から見分けます。`perception/oracle.py` の真値ラベルを
正解として、次の順に置き換えて精度を比べます。

1. 物体: 語彙を指定できる検出（例: Grounding DINO）＋セグメンテーション（例: SAM 2）
2. 汚れ: 物体検出が苦手な領域なので、真値ラベルで小さなセグメンテーションモデルを学習する
3. 物か汚れか迷うもの（こぼれた液体、紙ナプキン、パンくず）を VLM に判定させる

評価指標: 物体の検出率、汚れの IoU、「拭き残し面積」。

シミュレーション画像だけだと実物と見た目が違うので、テクスチャ・照明・カメラ位置をランダムに変える
（ドメインランダム化）仕組みを `scene.py` に足します。

### 1-2. 動かす（方策）

> 進み具合: 手書きの「コップをつかんでビンに入れる」が動いた（`control/pick_place.py`、
> 直径 5cm のコップで 10/10、ほかの食器があると 7/8）。腕が届くのはテーブル手前の約 30cm まで、
> 直径 7cm 以上の物は V 字のグリッパーから押し出される、という制約が分かった。

1. 手書きスクリプトでデモを作る（`scripts/demo_wipe.py` を、つかむ → ビンに入れる まで広げる）
2. デモを LeRobot のデータセット形式で保存する（実機で集めるデータと同じ形式にするため）
3. 模倣学習で方策を作り、成功率を比べる。候補:
   - ACT（ALOHA で使われた Transformer 方策）
   - Diffusion Policy
   - SmolVLA、π0 系などの VLA（言語指示つき。LeRobot から使える）
4. 片付けは「つかむ・運ぶ・置く」、拭き上げは「押し付けながら面を覆う」と性質が違うので、
   拭き上げは経路計画（汚れの位置から往復経路を作る）＋力の制御で作り、学習と比べる

「最新論文の実装」はこのフェーズで行います。採用する論文を決めたら、このファイルに
比較結果（成功率・学習時間・必要なデモ数）を書き足していきます。

### 1-3. 評価

- 片付け成功率（ビンに入れた数 / 物の数）、落下数
- 拭き残し率（`dirt_remaining`）
- 1 卓あたりの所要時間
- 乱数シードを固定した評価セット（例: 100 シーン）で毎回比べる

## フェーズ 2: XLeRobot 実機

- 部品購入と組み立て（XLeRobot の公式ドキュメントの BOM に従う）
- 遠隔操作（XLeRobot は VR・ゲームパッド・Joy-Con に対応）でデモを集める
- シミュレーションと実機で同じ行動・観測の形にそろえ、シミュレーションで作った方策をそのまま試す
- 実機のカメラ画像で認識モデルを再評価する
- スポンジ／ワイパーを手先に付ける治具を 3D プリントする

## フェーズ 3: 顧客での試験導入

- 安全: 速度と力の上限、人が近づいたら止まる、非常停止ボタン
- 店舗ごとのテーブルの寸法・食器・汚れの種類をシミュレーションに反映する
- 現場で失敗した場面を記録し、デモを足して再学習する、を繰り返す
- KPI: 片付け成功率、拭き残し率、1 卓あたりの時間、人の介入回数

## フェーズ 4: YOR

YOR は、全方向に動く台車・上下に伸びるリフト・6 自由度の腕 2 本を持つ、オープンソースの移動マニピュレータです。
Jetson と ZED カメラを積み、CAD・部品表・ソフトウェアが公開されています（部品代は 1 万ドル未満）。
リフトがあるので、XLeRobot より高さの違うテーブルや奥の物に届きます。

- 論文: [YOR: Your Own Mobile Manipulator for Generalizable Robotics (arXiv:2602.11150)](https://arxiv.org/abs/2602.11150)
- 組み立てドキュメント: <https://build.yourownrobot.ai/>

進め方:

1. 公開されている CAD / URDF から MuJoCo のモデル（MJCF）を作る
   - URDF があれば MuJoCo で読み込んで MJCF に書き出し、関節の範囲・アクチュエータ・質量を確認する
   - なければ CAD からリンクごとのメッシュを書き出して組む
2. `scene.py` のロボット部分を差し替えられるようにする（いまは XLeRobot 固定）。
   行動空間にリフトを加え、台車・腕の部分は XLeRobot と共通の形にする
3. XLeRobot で作った認識と方策を YOR のシミュレーションで評価する
4. 助成金の申請資料に、シミュレーションでの結果と XLeRobot での顧客試験の結果を使う
5. 購入後、実機で PoC
